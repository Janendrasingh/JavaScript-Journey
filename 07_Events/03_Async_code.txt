============================================================
ASYNCHRONOUS JAVASCRIPT
=======================

1. INTRODUCTION TO ASYNCHRONOUS JAVASCRIPT

---

JavaScript is a single-threaded programming language. This means it normally executes JavaScript code on one call stack, one operation at a time.

By default, JavaScript executes synchronous code sequentially, from top to bottom.

However, some operations take time to complete, such as:

* Fetching data from an API
* Reading files in supported environments
* Waiting for a timer
* Sending a network request
* Waiting for a user's response

If JavaScript had to wait for every time-consuming operation to finish before doing anything else, applications could become slow and unresponsive.

Asynchronous programming helps JavaScript start certain operations and continue executing other code while those operations are pending.

Example:

console.log("First");

setTimeout(() => {
console.log("Second");
}, 2000);

console.log("Third");

Output:

First
Third
Second

Explanation:

1. JavaScript prints "First".
2. setTimeout() schedules a callback to run after approximately 2 seconds.
3. JavaScript continues and prints "Third".
4. When the timer has expired and the callback can be processed, "Second" is printed.

IMPORTANT:
setTimeout() does not guarantee that the callback will execute at the exact specified time. It schedules the callback to become eligible for execution after the delay. The callback runs when the JavaScript runtime can process it.

============================================================
2. SYNCHRONOUS VS ASYNCHRONOUS CODE
===================================

## A. SYNCHRONOUS CODE

Synchronous code executes one operation at a time. The next operation waits for the current operation to finish.

Example:

console.log("Task 1");
console.log("Task 2");
console.log("Task 3");

Output:

Task 1
Task 2
Task 3

Explanation:

JavaScript executes each statement in order.

## B. ASYNCHRONOUS CODE

Asynchronous operations allow JavaScript to continue executing other code while certain operations are pending.

Example:

console.log("Task 1");

setTimeout(() => {
console.log("Task 2");
}, 1000);

console.log("Task 3");

Output:

Task 1
Task 3
Task 2

Explanation:

The timer callback is scheduled for later, allowing the remaining synchronous code to execute first.

DIFFERENCE:

Synchronous:

* Operations execute in sequence.
* A long-running operation can delay subsequent operations.
* The next statement normally waits for the current statement to finish.

Asynchronous:

* Certain operations can remain pending while other code executes.
* Callbacks, Promises, and async/await can help manage asynchronous work.
* The order of completion may differ from the order in which operations were started.

============================================================
3. WHY DO WE NEED ASYNCHRONOUS JAVASCRIPT?
==========================================

Consider a weather application.

The application needs to:

1. Display its interface.
2. Request weather information from an API.
3. Wait for the server to respond.
4. Display the weather information.

The server might take a few milliseconds or several seconds to respond.

Without suitable asynchronous APIs, waiting for network operations could block other work.

Asynchronous JavaScript allows applications to remain responsive while waiting for network responses, timers, and other asynchronous operations.

Common use cases:

* Fetching API data
* Loading images and other resources
* Handling timers
* Responding to user interactions
* Sending form data to a server
* Making database requests in environments such as Node.js

============================================================
4. HOW JAVASCRIPT HANDLES ASYNCHRONOUS CODE
===========================================

Several components work together to manage asynchronous operations.

## A. CALL STACK

The call stack tracks JavaScript functions that are currently executing.

Example:

function first() {
second();
}

function second() {
console.log("Hello");
}

first();

Output:

Hello

Execution:

1. first() is called and placed on the call stack.
2. first() calls second().
3. second() is placed on the call stack.
4. console.log() executes.
5. second() finishes and is removed from the stack.
6. first() finishes and is removed from the stack.

## B. WEB APIs / RUNTIME APIs

In a browser, APIs provided by the browser environment handle certain operations outside the normal execution of JavaScript code.

Examples include:

* Timers such as setTimeout()
* DOM event handling
* Network requests through fetch()
* Other browser-provided asynchronous operations

JavaScript itself does not implement every part of these operations. The JavaScript engine works with the surrounding runtime environment.

Node.js has its own runtime APIs and event loop mechanisms.

## C. CALLBACK QUEUE (TASK QUEUE)

Callbacks from certain asynchronous operations are scheduled to execute when the call stack is available.

For example, a setTimeout() callback is scheduled as a task after its timer delay has elapsed.

## D. MICROTASK QUEUE

Certain operations schedule callbacks as microtasks.

Examples include:

* Promise.then()
* Promise.catch()
* Promise.finally()
* The continuation of an async function after an awaited Promise settles

In browsers, microtasks are generally processed after the current JavaScript execution completes and before the event loop proceeds to the next task.

## E. EVENT LOOP

The event loop coordinates when queued asynchronous callbacks can execute.

At a simplified level:

1. JavaScript executes the current synchronous code.
2. When the call stack becomes available, queued microtasks are processed.
3. The runtime can then process a task, such as a timer callback or an event callback.
4. Microtasks scheduled during that task are processed at the appropriate checkpoint.

Simplified flow:

JavaScript Code
|
v
Call Stack
|
v
Runtime APIs handle asynchronous operations
|
v
Callbacks become eligible for scheduling
|
+----------------------+
|                      |
v                      v
Microtask Queue          Task Queue
|                      |
+----------+-----------+
|
v
Event Loop
|
v
Call Stack is available

This is a simplified illustration, not a complete specification of every browser scheduling rule.

IMPORTANT:
The event loop does not make every JavaScript operation run in parallel. Ordinary JavaScript execution on the main thread still runs one operation at a time.

5. UNDERSTANDING setTimeout()
=============================

setTimeout() schedules a callback to run after a specified delay.

Syntax:

setTimeout(callback, delay);

Example:

setTimeout(() => {
console.log("Hello after 2 seconds");
}, 2000);

Explanation:

* The first argument is the callback function.
* The second argument is the delay in milliseconds.
* 1000 milliseconds equals 1 second.
* The callback becomes eligible to run after the delay, subject to runtime scheduling.

Example:

console.log("Start");

setTimeout(() => {
console.log("Timer completed");
}, 2000);

console.log("End");

Output:

Start
End
Timer completed

IMPORTANT:
setTimeout() is not a command to pause the entire JavaScript program. It schedules a callback for later.

============================================================
6. UNDERSTANDING setInterval()
==============================

setInterval() schedules a callback to run repeatedly at a specified interval.

Syntax:

setInterval(callback, delay);

Example:

let count = 1;

const intervalId = setInterval(() => {
console.log(count);
count++;

```
if (count > 5) {
    clearInterval(intervalId);
}
```

}, 1000);

Output:

1
2
3
4
5

Explanation:

1. setInterval() schedules repeated callback executions.
2. Each execution prints the current count.
3. The count increases.
4. When count becomes greater than 5, clearInterval() stops the interval.

Difference between setTimeout() and setInterval():

setTimeout():

* Schedules a callback to run once after a delay.

setInterval():

* Schedules a callback to run repeatedly until the interval is cleared or otherwise stopped.

Use clearTimeout() to cancel a pending timeout.

Use clearInterval() to cancel a repeating interval.

============================================================
7. WHAT IS A CALLBACK FUNCTION?
===============================

A callback is a function passed to another function so that it can be called later or as part of another operation.

Example:

function greet(name, callback) {
console.log("Hello " + name);
callback();
}

function sayWelcome() {
console.log("Welcome to JavaScript");
}

greet("Janendra", sayWelcome);

Output:

Hello Janendra
Welcome to JavaScript

Explanation:

* sayWelcome is passed as an argument to greet().
* greet() executes its own console.log().
* greet() then invokes callback().
* The callback runs and prints the welcome message.

Callbacks can be used in both synchronous and asynchronous code.

Example of a synchronous callback:

[1, 2, 3].forEach((number) => {
console.log(number);
});

Example of an asynchronous callback:

setTimeout(() => {
console.log("Executed later");
}, 1000);

============================================================
8. CALLBACK HELL
================

Callback hell occurs when multiple asynchronous operations are nested inside one another, making the code difficult to read and maintain.

Example:

setTimeout(() => {
console.log("Step 1");

```
setTimeout(() => {
    console.log("Step 2");

    setTimeout(() => {
        console.log("Step 3");
    }, 1000);

}, 1000);
```

}, 1000);

The nested structure becomes difficult to manage as more operations are added.

Problems with callback hell:

* Code becomes deeply nested.
* Error handling becomes harder.
* Code is difficult to maintain.
* Understanding the execution flow becomes more complicated.

Promises and async/await provide alternative ways to structure many asynchronous workflows.

============================================================
9. WHAT IS A PROMISE?
=====================

A Promise is a JavaScript object that represents the eventual completion or failure of an asynchronous operation.

A Promise can have three states:

1. Pending:
   The operation has not yet settled.

2. Fulfilled:
   The operation completed successfully.

3. Rejected:
   The operation failed.

A settled Promise is either fulfilled or rejected.

Example:

const myPromise = new Promise((resolve, reject) => {
let success = true;

```
if (success) {
    resolve("Operation successful");
} else {
    reject("Operation failed");
}
```

});

myPromise
.then((result) => {
console.log(result);
})
.catch((error) => {
console.log(error);
});

Output:

Operation successful

Explanation:

* new Promise() creates a Promise.
* resolve() fulfills the Promise with a value.
* reject() rejects the Promise with a reason.
* .then() handles fulfillment.
* .catch() handles rejection.

IMPORTANT:
The Promise executor function passed to new Promise() runs synchronously. Promises do not automatically make synchronous code asynchronous.

============================================================
10. UNDERSTANDING resolve() AND reject()
========================================

resolve():
Used to fulfill a Promise with a successful result.

reject():
Used to reject a Promise because an operation failed.

Example:

const checkAge = new Promise((resolve, reject) => {
const age = 20;

```
if (age >= 18) {
    resolve("You are eligible");
} else {
    reject("You are not eligible");
}
```

});

checkAge
.then((message) => {
console.log(message);
})
.catch((error) => {
console.log(error);
});

Output:

You are eligible

Note:
resolve() and reject() are conventional parameter names for the functions provided to the Promise executor. You can use different names, but these names are standard and descriptive.

============================================================
11. PROMISE CHAINING
====================

Promise chaining allows multiple asynchronous operations to be organized in sequence.

Example:

Promise.resolve(10)
.then((number) => {
console.log(number);
return number * 2;
})
.then((number) => {
console.log(number);
return number + 5;
})
.then((number) => {
console.log(number);
});

Output:

10
20
25

Explanation:

1. Promise.resolve(10) creates a fulfilled Promise.
2. The first .then() receives 10 and returns 20.
3. The next .then() receives 20 and returns 25.
4. The final .then() prints 25.

Each .then() returns a new Promise, allowing the chain to continue.

Returning a Promise from a .then() handler allows the next step to wait for that Promise to settle.

============================================================
12. PROMISE METHODS
===================

A. Promise.resolve()

Creates a fulfilled Promise for a given value.

Example:

Promise.resolve("Success")
.then((value) => console.log(value));

Output:

Success

B. Promise.reject()

Creates a rejected Promise.

Example:

Promise.reject("Something went wrong")
.catch((error) => console.log(error));

Output:

Something went wrong

C. Promise.all()

Waits for all supplied Promises to fulfill.

If all fulfill, the result is an array of their values in input order.

If one rejects, Promise.all() rejects with that reason.

Example:

const promise1 = Promise.resolve("A");
const promise2 = Promise.resolve("B");
const promise3 = Promise.resolve("C");

Promise.all([promise1, promise2, promise3])
.then((results) => {
console.log(results);
});

Output:

["A", "B", "C"]

D. Promise.allSettled()

Waits for all supplied Promises to settle, whether they fulfill or reject.

Example:

const promise1 = Promise.resolve("Success");
const promise2 = Promise.reject("Failure");

Promise.allSettled([promise1, promise2])
.then((results) => {
console.log(results);
});

The result is an array describing each Promise's status and value or rejection reason.

E. Promise.race()

Settles with the outcome of the first supplied Promise to settle.

Example:

const promise1 = new Promise((resolve) => {
setTimeout(() => resolve("First"), 1000);
});

const promise2 = new Promise((resolve) => {
setTimeout(() => resolve("Second"), 2000);
});

Promise.race([promise1, promise2])
.then((result) => {
console.log(result);
});

Output:

First

F. Promise.any()

Fulfills with the first fulfilled Promise.

If every supplied Promise rejects, it rejects with an AggregateError.

Example:

const promise1 = Promise.reject("Error 1");
const promise2 = Promise.resolve("Success");
const promise3 = Promise.resolve("Another success");

Promise.any([promise1, promise2, promise3])
.then((result) => {
console.log(result);
});

Output:

Success

============================================================
13. WHAT IS async/await?
========================

async/await provides syntax for writing Promise-based asynchronous code in a style that resembles sequential code.

An async function always returns a Promise.

Example:

async function greet() {
return "Hello World";
}

greet().then((message) => {
console.log(message);
});

Output:

Hello World

Although the function returns a string in its body, JavaScript wraps that result in a fulfilled Promise.

The following two functions behave similarly:

function normalFunction() {
return Promise.resolve("Hello");
}

async function asyncFunction() {
return "Hello";
}

============================================================
14. UNDERSTANDING await
=======================

The await keyword is used inside async functions to wait for a Promise to settle before continuing that async function.

Example:

function getData() {
return new Promise((resolve) => {
setTimeout(() => {
resolve("Data received");
}, 2000);
});
}

async function showData() {
console.log("Start");

```
const result = await getData();

console.log(result);
console.log("End");
```

}

showData();

Output:

Start
Data received
End

Explanation:

1. showData() begins executing.
2. "Start" is printed.
3. getData() returns a Promise.
4. await suspends the continuation of showData() until the Promise settles.
5. Other JavaScript work can execute while the Promise is pending.
6. When the Promise fulfills, the function continues.
7. The result is printed.
8. "End" is printed.

IMPORTANT:
await does not block the entire JavaScript thread. It suspends the async function's continuation while other work can proceed.

============================================================
15. ERROR HANDLING WITH async/await
===================================

Use try...catch to handle errors in asynchronous functions.

Example:

function fetchData() {
return new Promise((resolve, reject) => {
const success = false;

```
    if (success) {
        resolve("Data loaded");
    } else {
        reject(new Error("Failed to load data"));
    }
});
```

}

async function displayData() {
try {
const result = await fetchData();
console.log(result);
} catch (error) {
console.log(error.message);
}
}

displayData();

Output:

Failed to load data

Explanation:

* try contains the code that may fail.
* catch handles an error or rejection.
* error.message provides the error message.

An async function can also be handled with .catch():

async function example() {
throw new Error("Something went wrong");
}

example().catch((error) => {
console.log(error.message);
});

============================================================
16. FETCH API
=============

The Fetch API is used to make HTTP requests, such as requesting data from a server.

Example:

fetch("https://jsonplaceholder.typicode.com/users/1")
.then((response) => {
if (!response.ok) {
throw new Error("HTTP error: " + response.status);
}

```
    return response.json();
})
.then((data) => {
    console.log(data);
})
.catch((error) => {
    console.log("Error:", error.message);
});
```

Explanation:

1. fetch() starts an HTTP request and returns a Promise.
2. The first .then() receives the Response object.
3. response.ok checks whether the HTTP status is in the 200–299 range.
4. response.json() reads the response body and returns a Promise.
5. The next .then() receives the parsed data.
6. .catch() handles network errors, parsing errors, and errors thrown in the chain.

IMPORTANT:
fetch() does not automatically reject its Promise for HTTP error statuses such as 404 or 500. Check response.ok when you need to treat these responses as errors.

============================================================
17. FETCH API USING async/await
===============================

The same request can be written using async/await.

async function getUser() {
try {
const response = await fetch(
"https://jsonplaceholder.typicode.com/users/1"
);

```
    if (!response.ok) {
        throw new Error("HTTP error: " + response.status);
    }

    const data = await response.json();

    console.log(data);
} catch (error) {
    console.log("Error:", error.message);
}
```

}

getUser();

This style is often easier to read when several asynchronous steps depend on one another.

18. EVENT LOOP: MICROTASKS VS TASKS
===================================

JavaScript uses different scheduling mechanisms for different kinds of callbacks.

Promise handlers are scheduled as microtasks.

Callbacks scheduled by setTimeout() are tasks.

Example:

console.log("A");

setTimeout(() => {
console.log("B");
}, 0);

Promise.resolve().then(() => {
console.log("C");
});

console.log("D");

Output:

A
D
C
B

Explanation:

1. "A" is printed immediately.
2. setTimeout() schedules a task.
3. Promise.then() schedules a microtask.
4. "D" is printed before asynchronous callbacks execute.
5. After the current synchronous code finishes, the Promise microtask runs.
6. The timer callback runs when its task is processed.

Therefore, the output is:

A
D
C
B

IMPORTANT:
setTimeout(callback, 0) does not mean that the callback executes immediately. It schedules the callback to run as a task when the runtime can process it.

20. COMMON MISTAKES IN ASYNCHRONOUS JAVASCRIPT
==============================================

MISTAKE 1: Forgetting to return a value from a Promise handler

Incorrect:

Promise.resolve(10)
.then((number) => {
number * 2;
})
.then((result) => {
console.log(result);
});

Output:

undefined

Correct:

Promise.resolve(10)
.then((number) => {
return number * 2;
})
.then((result) => {
console.log(result);
});

Output:

20

MISTAKE 2: Forgetting await

Incorrect:

async function getData() {
const result = fetch(
"https://jsonplaceholder.typicode.com/users/1"
);

```
console.log(result);
```

}

getData();

The variable result contains a Promise rather than the parsed user data.

Correct:

async function getData() {
const response = await fetch(
"https://jsonplaceholder.typicode.com/users/1"
);

```
if (!response.ok) {
    throw new Error("Request failed");
}

const data = await response.json();

console.log(data);
```

}

getData().catch((error) => {
console.log(error.message);
});

MISTAKE 3: Assuming fetch() rejects for every HTTP error

A 404 or 500 response does not automatically reject the Promise returned by fetch().

Check response.ok and handle the response accordingly.

MISTAKE 4: Using await outside an appropriate context

In a normal JavaScript script, await is generally used inside an async function.

Modern JavaScript modules also support top-level await.

MISTAKE 5: Forgetting error handling

Network requests can fail. Use .catch() or try...catch to handle errors appropriately.

21. INTERVIEW QUESTIONS AND ANSWERS
===================================

Q1. What is asynchronous JavaScript?

Asynchronous JavaScript allows certain operations to remain pending while other JavaScript code continues executing.

Q2. Is JavaScript single-threaded?

JavaScript normally executes code on one main-thread call stack in a browser. Runtime environments provide additional mechanisms for asynchronous operations and, where supported, parallel work.

Q3. What is the event loop?

The event loop coordinates the execution of queued tasks and microtasks when JavaScript can process them.

Q4. What is a callback?

A callback is a function passed to another function so that it can be invoked later or during another operation.

Q5. What is callback hell?

Callback hell is deeply nested callback code that becomes difficult to read, maintain, and handle errors in.

Q6. What is a Promise?

A Promise represents the eventual fulfillment or rejection of an operation.

Q7. What are the three Promise states?

Pending, fulfilled, and rejected.

Q8. What is the difference between then() and catch()?

.then() handles fulfillment and can also accept a rejection handler as a second argument. .catch() handles rejection and is commonly used for error handling.

Q9. What is async/await?

async/await is syntax for working with Promises in a more sequential-looking style.

Q10. What does await do?

await suspends the continuation of an async function until the awaited value settles if it is a Promise, allowing other JavaScript work to proceed.

Q11. Does setTimeout(callback, 0) execute immediately?

No. It schedules the callback as a task that runs when the runtime can process it.

Q12. What is the difference between Promise.all() and Promise.allSettled()?

Promise.all() rejects if any input Promise rejects. Promise.allSettled() waits for every input Promise to settle and reports each outcome.

Q13. Does fetch() reject when the server returns a 404 status?

Not just because of the HTTP status. Check response.ok to detect HTTP error responses.

Q14. What is the difference between a task and a microtask?

They are different scheduling categories. Promise handlers use the microtask queue, while setTimeout() callbacks use the task queue in browsers.

Q15. Can async functions return ordinary values?

Yes. An async function wraps a returned value in a fulfilled Promise. If it throws an error, the returned Promise rejects.
