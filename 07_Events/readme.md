# 1. Introduction to Event Handling

## What Is Event Handling?

Event handling is the process of detecting an event and executing JavaScript code in response to it.

An event might occur when:

* A user clicks a button.
* A user types into an input field.
* A form is submitted.
* A user presses a keyboard key.
* A webpage finishes loading.
* A mouse pointer enters or leaves an element.

JavaScript uses event handlers to respond to these actions.

### Example

**HTML:**

```html
<button id="btn">Click Me</button>
```

**JavaScript:**

```javascript
const button = document.querySelector("#btn");

button.addEventListener("click", function () {
    console.log("Button clicked!");
});
```

**Output after clicking the button:**

```text
Button clicked!
```

### How Does It Work?

1. `document.querySelector("#btn")` selects the button.
2. `addEventListener()` registers a listener for the `click` event.
3. When the user clicks the button, the browser dispatches a click event.
4. JavaScript executes the callback function.

**Important:** Registering an event listener does not immediately execute the callback. The callback runs when the corresponding event occurs.

# 2. What Is an Event?

An event is an occurrence that the browser makes available to JavaScript.

Events can be generated by user interactions, browser actions, or JavaScript code.

Examples:

| Action                           | Event       |
| -------------------------------- | ----------- |
| Clicking a button                | `click`     |
| Double-clicking an element       | `dblclick`  |
| Moving the mouse over an element | `mouseover` |
| Pressing a keyboard key          | `keydown`   |
| Releasing a keyboard key         | `keyup`     |
| Typing into an input             | `input`     |
| Changing a form control's value  | `change`    |
| Submitting a form                | `submit`    |
| Focusing an input                | `focus`     |
| Leaving an input                 | `blur`      |
| Loading a webpage                | `load`      |
| Scrolling a page                 | `scroll`    |

### Example

```html
<button id="btn">Click Me</button>

<script>
    document.querySelector("#btn").addEventListener("click", function () {
        console.log("A click event occurred.");
    });
</script>
```

The browser dispatches a `click` event when the user clicks the button.

# 4. Three Ways to Handle Events

There are three commonly discussed ways to attach event handlers.

## 4.1 Inline HTML Event Handler

An event handler can be written directly in an HTML attribute.

```html
<button onclick="showMessage()">Click Me</button>

<script>
    function showMessage() {
        console.log("Hello!");
    }
</script>
```

**Output:**

```text
Hello!
```

### Disadvantages

* Mixes HTML with JavaScript.
* Becomes difficult to maintain in large projects.
* Makes event logic harder to organize.
* Only one handler is represented by a given inline event-handler attribute.

Inline event handlers are generally avoided in modern applications.

## 4.2 DOM Event Handler Property

You can assign a function to an element's event-handler property.

```html
<button id="btn">Click Me</button>

<script>
    const button = document.querySelector("#btn");

    button.onclick = function () {
        console.log("Button clicked!");
    };
</script>
```

This works, but assigning a new function to `onclick` replaces the previous handler assigned to that property.

```javascript
button.onclick = function () {
    console.log("First handler");
};

button.onclick = function () {
    console.log("Second handler");
};
```

When the button is clicked, only the second assigned handler runs.

## 4.3 Using `addEventListener()`

This is generally the preferred method.

```html
<button id="btn">Click Me</button>

<script>
    const button = document.querySelector("#btn");

    button.addEventListener("click", function () {
        console.log("First handler");
    });

    button.addEventListener("click", function () {
        console.log("Second handler");
    });
</script>
```

**Output after one click:**

```text
First handler
Second handler
```

Both listeners are registered and run when the event is dispatched, unless another behavior prevents them from running.

### Comparison

| Feature                                       | Inline Handler                 | DOM Property                               | `addEventListener()`               |
| --------------------------------------------- | ------------------------------ | ------------------------------------------ | ---------------------------------- |
| Written in HTML                               | Yes                            | No                                         | No                                 |
| Supports multiple handlers for the same event | Not through the same attribute | No, only one property assignment at a time | Yes                                |
| Supports capture option                       | No                             | No                                         | Yes                                |
| Easy to remove a specific handler             | Limited                        | Can assign `null`                          | Yes, using `removeEventListener()` |
| Generally preferred for modern code           | No                             | Sometimes                                  | Yes                                |

# 5. The `addEventListener()` Method

## What Is `addEventListener()`?

`addEventListener()` registers a function that should run when a particular event occurs on an element.

### Syntax

```javascript
element.addEventListener(eventType, callback, options);
```

### Parameters

**1. `eventType`**

The name of the event, such as `"click"` or `"keydown"`.

**2. `callback`**

The function that should run when the event occurs.

**3. `options`**

An optional Boolean or options object that controls how the listener behaves.

### Basic Example

```html
<button id="btn">Click Me</button>

<script>
    const button = document.querySelector("#btn");

    button.addEventListener("click", function () {
        console.log("Button clicked!");
    });
</script>
```

### Using an Arrow Function

```javascript
button.addEventListener("click", () => {
    console.log("Button clicked!");
});
```

### Using a Named Function

```javascript
function handleClick() {
    console.log("Button clicked!");
}

button.addEventListener("click", handleClick);
```

**Important:** When passing a named function as a callback, write `handleClick`, not `handleClick()`.

```javascript
button.addEventListener("click", handleClick);   // Correct
button.addEventListener("click", handleClick()); // Usually incorrect
```

The first form passes the function itself. The second executes the function immediately and passes its return value.

# 6. The Event Object

## What Is the Event Object?

When an event occurs, the browser provides an event object containing information about that event.

You can receive this object as a parameter in the event-handler callback.

### Example

```html
<button id="btn">Click Me</button>

<script>
    const button = document.querySelector("#btn");

    button.addEventListener("click", function (event) {
        console.log(event);
    });
</script>
```

Click the button and inspect the event object in the browser console.

### Using the Event Object

```javascript
button.addEventListener("click", function (event) {
    console.log(event.type);
    console.log(event.target);
});
```

When the button is clicked, the output includes:

```text
click
<button id="btn">Click Me</button>
```

The browser displays the button element as a DOM element in the console.

### What Information Does the Event Object Provide?

Depending on the event type, the event object can provide:

* The event type.
* The element where the event originated.
* The element currently handling the event.
* Mouse coordinates.
* Keyboard key information.
* Whether the default action was prevented.
* Methods for controlling propagation and default behavior.

### Why Is It Useful?

The event object lets you write dynamic code that responds to what actually happened rather than executing the same action without context.

# 7. Important Event Properties

## 7.1 `event.type`

Returns the event type.

```javascript
document.querySelector("#btn").addEventListener("click", function (event) {
    console.log(event.type);
});
```

**Output:**

```text
click
```

## 7.2 `event.target`

Identifies the original event target.

```javascript
document.querySelector("#btn").addEventListener("click", function (event) {
    console.log(event.target);
});
```

The target is usually the element where the event originated.

## 7.3 `event.currentTarget`

Identifies the element whose listener is currently running.

```javascript
document.querySelector("#btn").addEventListener("click", function (event) {
    console.log(event.currentTarget);
});
```

In this example, both `target` and `currentTarget` will usually refer to the button because the listener is attached directly to it.

They can differ when an event propagates through nested elements.

## 7.4 `event.clientX` and `event.clientY`

For mouse and pointer events, these properties give the pointer's coordinates relative to the viewport.

```javascript
document.addEventListener("click", function (event) {
    console.log("X:", event.clientX);
    console.log("Y:", event.clientY);
});
```

The values are measured from the top-left corner of the viewport.

## 7.5 `event.key`

For keyboard events, `event.key` describes the key value associated with the event.

```javascript
document.addEventListener("keydown", function (event) {
    console.log(event.key);
});
```

If the user presses the letter A, the output will typically be:

```text
a
```

The value may differ based on modifiers, keyboard layout, and the key pressed.

## 7.6 `event.code`

For keyboard events, `event.code` identifies the physical key position using a standardized code.

```javascript
document.addEventListener("keydown", function (event) {
    console.log("Key:", event.key);
    console.log("Code:", event.code);
});
```

For a typical US keyboard, pressing the A key without Shift produces values similar to:

```text
Key: a
Code: KeyA
```

Use `key` when you care about the character or key value. Use `code` when you care about the physical key position.

## 7.7 `event.bubbles`

Indicates whether the event bubbles.

```javascript
button.addEventListener("click", function (event) {
    console.log(event.bubbles);
});
```

For a typical click event, this prints `true`.

## 7.8 `event.cancelable`

Indicates whether the event's default action can be canceled.

```javascript
button.addEventListener("click", function (event) {
    console.log(event.cancelable);
});
```

The result depends on the event type.

## 7.9 `event.defaultPrevented`

Indicates whether the event's default action has been prevented.

```javascript
document.querySelector("form").addEventListener("submit", function (event) {
    event.preventDefault();

    console.log(event.defaultPrevented);
});
```

**Output:**

```text
true
```

This works because the handler prevents the default form-submission behavior before checking the property.

# 8. Event Propagation

## What Is Event Propagation?

Event propagation describes how an event travels through the DOM when it is dispatched.

For events that participate in propagation, the standard model has three phases:

1. Capturing phase
2. Target phase
3. Bubbling phase

Consider this HTML:

```html
<div id="parent">
    Parent
    <button id="child">Child</button>
</div>
```

The button is inside the parent `<div>`.

When the button is clicked, the click event can travel through the relevant DOM ancestors.

## The Three Phases

### Phase 1: Capturing

The event travels from the outer ancestors toward the target.

### Phase 2: Target

The event reaches the target element.

### Phase 3: Bubbling

The event travels from the target back through its ancestors.

**Important:** Not every event bubbles, and some events do not participate in all phases in the same way. Click events are a useful example because they normally bubble.

# 9. Event Bubbling

## What Is Event Bubbling?

Event bubbling means that an event originating on a nested element can propagate upward through its ancestors.

### Example

```html
<div id="parent" style="padding: 30px; background: lightblue;">
    Parent
    <button id="child">Click Me</button>
</div>

<script>
    const parent = document.querySelector("#parent");
    const child = document.querySelector("#child");

    parent.addEventListener("click", function () {
        console.log("Parent clicked");
    });

    child.addEventListener("click", function () {
        console.log("Child clicked");
    });
</script>
```

Click the button.

**Output:**

```text
Child clicked
Parent clicked
```

### Why?

1. The click event reaches the button.
2. The button's listener runs.
3. The event bubbles upward.
4. The parent's listener runs.

The parent listener runs even though the user clicked the child button.

This behavior is called event bubbling.

# 10. Event Capturing

## What Is Event Capturing?

Event capturing allows a listener to run during the capturing phase, as the event travels from ancestors toward the target.

### Syntax

```javascript
element.addEventListener("click", callback, true);
```

The third argument `true` enables capture mode.

### Example

```html
<div id="parent">
    Parent
    <button id="child">Click Me</button>
</div>

<script>
    const parent = document.querySelector("#parent");
    const child = document.querySelector("#child");

    parent.addEventListener("click", function () {
        console.log("Parent capturing");
    }, true);

    child.addEventListener("click", function () {
        console.log("Child clicked");
    });
</script>
```

**Output after clicking the button:**

```text
Parent capturing
Child clicked
```

The parent's capturing listener runs before the event reaches the child.

### Using an Options Object

```javascript
parent.addEventListener("click", function () {
    console.log("Capturing phase");
}, {
    capture: true
});
```

### Bubbling vs Capturing

| Feature                | Capturing                                       | Bubbling                                      |
| ---------------------- | ----------------------------------------------- | --------------------------------------------- |
| Direction              | Ancestors toward target                         | Target toward ancestors                       |
| Listener configuration | `true` or `{ capture: true }`                   | `false` or `{ capture: false }`               |
| Common default         | Not enabled                                     | Used for listeners registered without capture |
| Typical use            | Handling an event before it reaches descendants | Event delegation and ancestor-level handling  |

**Note:** Listener order can become more complex when multiple listeners are attached to the same target and different phases are involved.

# 11. `stopPropagation()`

## What Does `stopPropagation()` Do?

`event.stopPropagation()` prevents the event from continuing to propagate to other elements.

It does not automatically prevent the browser's default action.

### Example

```html
<div id="parent">
    Parent
    <button id="child">Click Me</button>
</div>

<script>
    const parent = document.querySelector("#parent");
    const child = document.querySelector("#child");

    parent.addEventListener("click", function () {
        console.log("Parent clicked");
    });

    child.addEventListener("click", function (event) {
        event.stopPropagation();

        console.log("Child clicked");
    });
</script>
```

**Output after clicking the button:**

```text
Child clicked
```

The event does not bubble to the parent's listener.

### Important Difference

`stopPropagation()`:

* Stops propagation to other elements.
* Does not cancel the default browser action.
* Does not prevent other listeners on the same element from running.

To stop other listeners on the same element as well, JavaScript provides `stopImmediatePropagation()`. Use it only when that behavior is actually required.

# 12. `preventDefault()`

## What Does `preventDefault()` Do?

`event.preventDefault()` prevents the browser's default action for a cancelable event.

It does not stop event propagation.

### Example: Preventing Form Submission

```html
<form id="myForm">
    <input type="text" id="username" placeholder="Enter username">

    <button type="submit">Submit</button>
</form>

<script>
    const form = document.querySelector("#myForm");

    form.addEventListener("submit", function (event) {
        event.preventDefault();

        console.log("Form submission prevented");
    });
</script>
```

**Output after submitting the form:**

```text
Form submission prevented
```

The browser does not perform the form's normal submission action.

### Example: Preventing Link Navigation

```html
<a href="https://example.com" id="myLink">Visit Website</a>

<script>
    document.querySelector("#myLink").addEventListener("click", function (event) {
        event.preventDefault();

        console.log("Navigation prevented");
    });
</script>
```

Clicking the link prints the message without navigating to the destination.

### `stopPropagation()` vs `preventDefault()`

| Method                       | Purpose                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------ |
| `stopPropagation()`          | Stops the event from continuing through the DOM                                |
| `preventDefault()`           | Prevents a cancelable default browser action                                   |
| `stopImmediatePropagation()` | Stops propagation and prevents later listeners on the same target from running |

**Remember:** These methods solve different problems.

# 13. Event Delegation

## What Is Event Delegation?

Event delegation is a technique in which a single event listener is attached to a common ancestor instead of attaching separate listeners to many child elements.

It relies on event propagation, usually bubbling.

### Without Event Delegation

```html
<ul id="languages">
    <li>JavaScript</li>
    <li>Python</li>
    <li>Java</li>
</ul>

<script>
    const items = document.querySelectorAll("#languages li");

    items.forEach(function (item) {
        item.addEventListener("click", function () {
            console.log(item.textContent);
        });
    });
</script>
```

This attaches a separate listener to every list item.

### With Event Delegation

```html
<ul id="languages">
    <li>JavaScript</li>
    <li>Python</li>
    <li>Java</li>
</ul>

<script>
    const list = document.querySelector("#languages");

    list.addEventListener("click", function (event) {
        if (event.target.matches("li")) {
            console.log(event.target.textContent);
        }
    });
</script>
```

Clicking a list item prints its text.

### How Does It Work?

1. A listener is attached to the parent `<ul>`.
2. The user clicks a child `<li>`.
3. The click event bubbles up to the `<ul>`.
4. `event.target` identifies the clicked element.
5. `matches("li")` checks whether the target is a list item.
6. The handler processes the click.

### Handling Nested Elements

If a list item contains a nested element, `event.target` might refer to that nested element rather than the `<li>`.

Use `closest()` to find the nearest matching list item.

```html
<ul id="languages">
    <li><span>JavaScript</span></li>
    <li><span>Python</span></li>
    <li><span>Java</span></li>
</ul>

<script>
    const list = document.querySelector("#languages");

    list.addEventListener("click", function (event) {
        const item = event.target.closest("li");

        if (item && list.contains(item)) {
            console.log(item.textContent);
        }
    });
</script>
```

### Advantages of Event Delegation

* Fewer event listeners.
* Less repeated code.
* Handles dynamically added children.
* Can simplify management of large lists and tables.

### Example: Adding New List Items

```html
<input type="text" id="languageInput" placeholder="Enter a language">
<button id="addButton">Add</button>

<ul id="languages">
    <li>JavaScript</li>
</ul>

<script>
    const list = document.querySelector("#languages");
    const input = document.querySelector("#languageInput");
    const button = document.querySelector("#addButton");

    list.addEventListener("click", function (event) {
        const item = event.target.closest("li");

        if (item && list.contains(item)) {
            console.log("Selected:", item.textContent);
        }
    });

    button.addEventListener("click", function () {
        const language = input.value.trim();

        if (language === "") {
            return;
        }

        const li = document.createElement("li");
        li.textContent = language;

        list.appendChild(li);
        input.value = "";
    });
</script>
```

The newly added list items work with the same delegated listener. There is no need to register a new listener for every item.

# 14. Mouse Events

Mouse events respond to mouse interactions.

## 14.1 `click`

Occurs when an element is clicked.

```javascript
button.addEventListener("click", function () {
    console.log("Clicked");
});
```

## 14.2 `dblclick`

Occurs when an element is double-clicked.

```javascript
button.addEventListener("dblclick", function () {
    console.log("Double-clicked");
});
```

## 14.3 `mousedown`

Occurs when a mouse button is pressed over an element.

```javascript
button.addEventListener("mousedown", function () {
    console.log("Mouse button pressed");
});
```

## 14.4 `mouseup`

Occurs when a mouse button is released.

```javascript
button.addEventListener("mouseup", function () {
    console.log("Mouse button released");
});
```

## 14.5 `mousemove`

Occurs as the mouse pointer moves.

```javascript
document.addEventListener("mousemove", function (event) {
    console.log(event.clientX, event.clientY);
});
```

This event can fire frequently. Avoid performing unnecessarily expensive work inside its handler.

## 14.6 `mouseenter` and `mouseleave`

```javascript
const box = document.querySelector("#box");

box.addEventListener("mouseenter", function () {
    console.log("Mouse entered");
});

box.addEventListener("mouseleave", function () {
    console.log("Mouse left");
});
```

These events do not bubble.

## 14.7 `mouseover` and `mouseout`

```javascript
box.addEventListener("mouseover", function () {
    console.log("Mouse over");
});

box.addEventListener("mouseout", function () {
    console.log("Mouse out");
});
```

These events bubble and can also fire as the pointer moves between an element and its descendants.

### Mouse Event Comparison

| Event         | Description                               |
| ------------- | ----------------------------------------- |
| `click`       | Mouse click                               |
| `dblclick`    | Double-click                              |
| `mousedown`   | Mouse button pressed                      |
| `mouseup`     | Mouse button released                     |
| `mousemove`   | Pointer moved                             |
| `mouseenter`  | Pointer entered the element               |
| `mouseleave`  | Pointer left the element                  |
| `mouseover`   | Pointer entered an element or descendant  |
| `mouseout`    | Pointer left an element or descendant     |
| `contextmenu` | Context-menu action, commonly right-click |

# 15. Keyboard Events

Keyboard events respond to keyboard input.

The main events are:

* `keydown`
* `keyup`

## 15.1 `keydown`

Occurs when a key is pressed.

```javascript
document.addEventListener("keydown", function (event) {
    console.log("Key pressed:", event.key);
});
```

## 15.2 `keyup`

Occurs when a key is released.

```javascript
document.addEventListener("keyup", function (event) {
    console.log("Key released:", event.key);
});
```

## 15.3 Detecting the Enter Key

```html
<input type="text" id="username" placeholder="Enter your name">

<script>
    const input = document.querySelector("#username");

    input.addEventListener("keydown", function (event) {
        if (event.key === "Enter") {
            console.log("Enter key pressed");
        }
    });
</script>
```

## 15.4 Detecting Modifier Keys

```javascript
document.addEventListener("keydown", function (event) {
    if (event.ctrlKey && event.key.toLowerCase() === "s") {
        event.preventDefault();

        console.log("Ctrl + S detected");
    }
});
```

This detects Ctrl+S and prevents its normal browser action when the event is cancelable.

**Important:** Keyboard shortcuts should be designed carefully so they do not interfere with browser, assistive-technology, or operating-system shortcuts unnecessarily.

# 16. Form Events

Form events are essential when building login forms, registration forms, search forms, and other interactive applications.

## 16.1 The `submit` Event

The `submit` event fires when a form is submitted, such as when the user activates a submit button or submits the form through an appropriate keyboard action.

```html
<form id="loginForm">
    <input type="text" id="username" placeholder="Username">
    <button type="submit">Login</button>
</form>

<script>
    const form = document.querySelector("#loginForm");

    form.addEventListener("submit", function (event) {
        event.preventDefault();

        console.log("Form submitted");
    });
</script>
```

### Why Use `preventDefault()`?

A normal form submission can navigate to another page or send form data according to the form's configuration.

Calling `preventDefault()` lets JavaScript handle the submission instead.

## 16.2 Basic Form Validation

```html
<form id="registrationForm">
    <input type="text" id="username" placeholder="Enter username">
    <button type="submit">Register</button>
    <p id="message"></p>
</form>

<script>
    const form = document.querySelector("#registrationForm");
    const username = document.querySelector("#username");
    const message = document.querySelector("#message");

    form.addEventListener("submit", function (event) {
        event.preventDefault();

        if (username.value.trim() === "") {
            message.textContent = "Username is required.";
            return;
        }

        message.textContent = "Registration form submitted!";
    });
</script>
```

The form is validated when submitted. This example does not send data to a server.

## 16.3 The `reset` Event

The `reset` event occurs when a form is reset.

```html
<form id="myForm">
    <input type="text" placeholder="Enter name">
    <button type="reset">Reset</button>
</form>

<script>
    document.querySelector("#myForm").addEventListener("reset", function () {
        console.log("Form reset");
    });
</script>
```

The event handler observes the reset action. It does not prevent the reset unless `preventDefault()` is called.

# 17. Input and Change Events

## 17.1 The `input` Event

The `input` event fires when a user action changes the value of an input, textarea, or editable element.

```html
<input type="text" id="name" placeholder="Type something">
<p id="output"></p>

<script>
    const input = document.querySelector("#name");
    const output = document.querySelector("#output");

    input.addEventListener("input", function () {
        output.textContent = input.value;
    });
</script>
```

As the user types, the output updates.

## 17.2 The `change` Event

The `change` event fires when a value change is committed according to the behavior of the relevant control.

```html
<select id="language">
    <option value="">Select a language</option>
    <option value="JavaScript">JavaScript</option>
    <option value="Python">Python</option>
</select>

<script>
    const select = document.querySelector("#language");

    select.addEventListener("change", function () {
        console.log("Selected:", select.value);
    });
</script>
```

### `input` vs `change`

| Feature        | `input`                                        | `change`                                                        |
| -------------- | ---------------------------------------------- | --------------------------------------------------------------- |
| Main purpose   | Detect value changes as they occur             | Detect a committed change                                       |
| Text input     | Usually fires as the user edits                | Usually fires when the edited value is committed, often on blur |
| Select control | Fires as its value changes                     | Fires when the selection is changed                             |
| Useful for     | Live search, character counters, live previews | Selection changes and committed values                          |

Exact timing depends on the type of form control.

    console.log("Page and dependent resources loaded");

window.addEventListener("resize", function () {

window.addEventListener("scroll", function () {

This can be useful for pausing nonessential updates when the user switches to another tab.

# 20. Event Listener Options

The third argument of `addEventListener()` can be a Boolean or an options object.

### Syntax

```javascript
element.addEventListener("click", handler, {
    capture: false,
    once: false,
    passive: false,
    signal: undefined
});
```

## 20.1 `capture`

Determines whether the listener runs during the capturing phase.

```javascript
element.addEventListener("click", handler, {
    capture: true
});
```

## 20.2 `once`

If set to `true`, the listener is automatically removed after it runs once.

```javascript
button.addEventListener("click", function () {
    console.log("This runs only once");
}, {
    once: true
});
```

Subsequent clicks do not trigger this listener.

## 20.3 `passive`

Indicates that the listener will not call `preventDefault()`.

```javascript
window.addEventListener("scroll", function () {
    console.log("Scrolling");
}, {
    passive: true
});
```

This option is useful for certain high-frequency input events. A passive listener should not attempt to cancel the event's default action.

## 20.4 `signal`

A listener can be associated with an `AbortSignal`, allowing it to be removed when the associated controller is aborted.

```javascript
const controller = new AbortController();

button.addEventListener("click", function () {
    console.log("Clicked");
}, {
    signal: controller.signal
});

// Remove listeners registered with this signal.
controller.abort();
```

# 21. Removing Event Listeners

The `removeEventListener()` method removes a previously registered event listener.

### Syntax

```javascript
element.removeEventListener(eventType, callback, options);
```

### Example

```html
<button id="btn">Click Me</button>

<script>
    const button = document.querySelector("#btn");

    function handleClick() {
        console.log("Button clicked");
    }

    button.addEventListener("click", handleClick);

    button.removeEventListener("click", handleClick);
</script>
```

Because the listener is removed before the button is clicked, it does not run when the button is clicked later.

### Important Rule

To remove a listener, you must pass the same function reference used when registering it. The event type and capture setting must also match.

This will not work as intended:

```javascript
button.addEventListener("click", function () {
    console.log("Clicked");
});

button.removeEventListener("click", function () {
    console.log("Clicked");
});
```

The two anonymous functions are different function objects.

### Correct Approach

```javascript
function handleClick() {
    console.log("Clicked");
}

button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

# 22. The `target` and `currentTarget` Properties

These properties are important for understanding event delegation and propagation.

Consider this HTML:

```html
<div id="parent">
    <button id="child">
        <span id="text">Click Me</span>
    </button>
</div>
```

### Example

```javascript
document.querySelector("#parent").addEventListener("click", function (event) {
    console.log("Target:", event.target);
    console.log("Current target:", event.currentTarget);
});
```

If the user clicks the nested `<span>`, the values will refer to:

* `event.target`: the `<span>` where the event originated.
* `event.currentTarget`: the parent `<div>` whose listener is running.

### Comparison

| Property              | Meaning                                       |
| --------------------- | --------------------------------------------- |
| `event.target`        | Original target of the event                  |
| `event.currentTarget` | Element whose listener is currently executing |

**Remember:** The target usually remains the same as the event propagates. The current target changes as different listeners handle the event.

# 23. The `this` Keyword in Event Handlers

The value of `this` depends on how the callback is defined and invoked.

## 23.1 Regular Function

```javascript
const button = document.querySelector("#btn");

button.addEventListener("click", function () {
    console.log(this);
});
```

For a regular function used as an event listener, `this` refers to the element to which the listener is attached.

In this example, it refers to the button.

## 23.2 Arrow Function

```javascript
button.addEventListener("click", () => {
    console.log(this);
});
```

An arrow function does not have its own `this`. It inherits `this` from its surrounding lexical context.

Therefore, `this` here is not automatically the button.

Use `event.currentTarget` when you need to identify the element whose listener is running:

```javascript
button.addEventListener("click", (event) => {
    console.log(event.currentTarget);
});
```

# 24. Event Handling with Arrow Functions

Arrow functions are commonly used with `addEventListener()`.

### Example

```javascript
const button = document.querySelector("#btn");

button.addEventListener("click", () => {
    console.log("Button clicked");
});
```

### With an Event Object

```javascript
button.addEventListener("click", (event) => {
    console.log(event.type);
    console.log(event.currentTarget);
});
```

### When Should You Use a Regular Function?

Use a regular function when you want the callback's `this` value to refer to the element receiving the event.

Use an arrow function when you want to retain `this` from the surrounding scope or do not need `this`.

Both styles are valid. Choose the one that makes the code easiest to understand.

# 25. Asynchronous Event Handling

Event handlers often initiate asynchronous operations, such as fetching data from a server.

An event callback can be declared with `async`.

### Example: Button Click with `async`

```html
<button id="loadButton">Load Data</button>

<script>
    const button = document.querySelector("#loadButton");

    button.addEventListener("click", async function () {
        console.log("Loading...");

        await new Promise(resolve => setTimeout(resolve, 1000));

        console.log("Finished loading");
    });
</script>
```

**Output:**

```text
Loading...
Finished loading
```

The second message appears after approximately one second.

### Important Concepts

* Event listeners do not automatically wait for asynchronous callbacks to finish.
* `async` functions return promises.
* `await` pauses the async function until the awaited promise settles.
* Errors from asynchronous work should be handled appropriately.

### Example: Handling Errors

```javascript
button.addEventListener("click", async function () {
    try {
        const response = await fetch("/api/data");

        if (!response.ok) {
            throw new Error("Request failed");
        }

        const data = await response.json();

        console.log(data);
    } catch (error) {
        console.error("Unable to load data:", error);
    }
});
```

The URL `/api/data` is an example endpoint. It must be replaced with an endpoint available in your application.

# 26. Common Mistakes

## Mistake 1: Calling the Function Immediately

Incorrect:

```javascript
button.addEventListener("click", handleClick());
```

Correct:

```javascript
button.addEventListener("click", handleClick);
```

The correct version passes the function reference.

## Mistake 2: Forgetting the Event Type

Incorrect:

```javascript
button.addEventListener(handleClick);
```

Correct:

```javascript
button.addEventListener("click", handleClick);
```

The event type is required.

## Mistake 3: Using the Wrong Selector

Incorrect:

```javascript
document.querySelector("btn");
```

Correct for an element with `id="btn"`:

```javascript
document.querySelector("#btn");
```

Use `#` for IDs and `.` for classes.

## Mistake 4: Selecting an Element Before It Exists

If a script runs before the relevant HTML has been parsed, `querySelector()` may return `null`.

One solution is to place the script at the end of the body.

```html
<body>
    <button id="btn">Click Me</button>

    <script src="script.js"></script>
</body>
```

Another solution is to use a deferred external script:

```html
<script src="script.js" defer></script>
```

## Mistake 5: Confusing `preventDefault()` with `stopPropagation()`

Incorrect assumption: Both methods do the same thing.

Correct understanding:

* `preventDefault()` cancels a cancelable default action.
* `stopPropagation()` stops further propagation through the DOM.

## Mistake 6: Using a New Function When Removing a Listener

Incorrect:

```javascript
button.addEventListener("click", function () {
    console.log("Clicked");
});

button.removeEventListener("click", function () {
    console.log("Clicked");
});
```

Correct:

```javascript
function handleClick() {
    console.log("Clicked");
}

button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

## Mistake 7: Forgetting That Dynamically Added Elements Need Handling

A listener attached directly to an element does not automatically apply to other elements created later.

Use event delegation when it fits the application.

## Mistake 8: Assuming Every Event Bubbles

Not all events bubble. For example, `focus` and `blur` do not bubble, while `focusin` and `focusout` do.

Check the behavior of the specific event before relying on propagation.

## Mistake 9: Using `innerHTML` for Plain Text

For plain text, prefer `textContent`.

```javascript
element.textContent = userInput;
```

This avoids interpreting the input as HTML and is safer when displaying untrusted text.

## Mistake 10: Performing Expensive Work in High-Frequency Events

Events such as `mousemove`, `scroll`, and `resize` can fire frequently.

Avoid repeatedly performing expensive calculations or DOM updates without a good reason. Consider throttling, debouncing, or `requestAnimationFrame()` depending on the task.

---

# 27. Best Practices

1. Prefer `addEventListener()` over inline event handlers.
2. Use meaningful function names, such as `handleSubmit` and `handleClick`.
3. Use `preventDefault()` only when you intend to override the browser's default action.
4. Use `stopPropagation()` only when stopping propagation is necessary.
5. Prefer event delegation for large or dynamically generated collections of similar elements.
6. Use `event.target` and `event.currentTarget` correctly.
7. Remove listeners when they are no longer needed, especially in long-lived interfaces.
8. Use `textContent` for displaying plain text.
9. Validate form inputs on the client for usability, and validate them again on the server when security matters.
10. Use semantic HTML elements such as `<button>` and `<form>` to support keyboard interaction and accessibility.
11. Do not rely only on color to communicate an event result; provide meaningful text or other accessible feedback.
12. Handle errors when event handlers initiate asynchronous work.
13. Use passive listeners when appropriate for events where the handler will not cancel the default action.
14. Test mouse, keyboard, and touch interactions where relevant.
15. Keep event handlers small and move complex logic into separate functions.

# 28. Interview Questions

## Basic Questions

### Q1. What is event handling in JavaScript?

Event handling is the process of responding to browser or user events by executing JavaScript code.

### Q2. What is an event listener?

An event listener is a registered callback that runs when a specified event occurs.

### Q3. What is `addEventListener()`?

It registers an event listener on an element or other event target.

### Q4. What is the event object?

The event object contains information about a dispatched event, including its type, target, and other event-specific details.

### Q5. What is the difference between `onclick` and `addEventListener()`?

`onclick` is a single event-handler property. `addEventListener()` supports multiple listeners for the same event and provides options such as capture, once, and passive.

## Intermediate Questions

### Q6. What is event bubbling?

Event bubbling is the propagation of an event from its target toward its ancestors.

### Q7. What is event capturing?

Event capturing is the propagation phase in which the event travels from ancestors toward its target.

### Q8. What is event delegation?

Event delegation attaches a listener to a common ancestor and uses event propagation to handle events originating from its descendants.

### Q9. What is the difference between `target` and `currentTarget`?

`target` identifies the event's original target. `currentTarget` identifies the element whose listener is currently running.

### Q10. What does `preventDefault()` do?

It prevents the default action of a cancelable event.

### Q11. What does `stopPropagation()` do?

It prevents an event from continuing to propagate through the DOM.

### Q12. Does `stopPropagation()` prevent other listeners on the same element from running?

No. It stops propagation to other elements, but it does not by itself stop other listeners on the same element. `stopImmediatePropagation()` can stop later listeners on the same target.

### Q13. What is the difference between `input` and `change`?

`input` generally fires as a value is edited, while `change` fires when a change is committed according to the control's behavior.

### Q14. How do you remove an event listener?

Use `removeEventListener()` with the same event type, callback function reference, and matching capture setting.

### Q15. What is the difference between `mouseenter` and `mouseover`?

`mouseenter` does not bubble and does not fire merely because the pointer moves into a descendant. `mouseover` bubbles and can fire when the pointer moves between an element and its descendants.

## Advanced Questions

### Q16. What is the event propagation model?

For events that participate in the standard propagation model, the phases are capturing, target, and bubbling.

### Q17. Why is event delegation useful for dynamic elements?

The listener is attached to an ancestor that already exists, so it can handle events from matching descendants added later.

### Q18. What is a passive event listener?

A passive listener promises not to call `preventDefault()`. It can help the browser optimize certain input interactions.

### Q19. What is the difference between `DOMContentLoaded` and `load`?

`DOMContentLoaded` fires when the document has been parsed and the DOM is ready. `load` waits for the window's dependent resources to finish loading.

### Q20. Can an event listener be asynchronous?

Yes. Its callback can be declared `async`, but the browser's event-dispatch mechanism does not automatically wait for the returned promise to settle.

# 30. Summary

JavaScript event handling makes webpages interactive by allowing code to respond to user actions and browser events.

The most important concepts are:

* **`addEventListener()`** registers event callbacks.
* **Event objects** provide information about dispatched events.
* **Event bubbling** allows events to propagate from a target toward its ancestors.
* **Event capturing** allows listeners to run while events travel toward their targets.
* **`preventDefault()`** cancels a cancelable default action.
* **`stopPropagation()`** stops further event propagation.
* **Event delegation** handles events from multiple descendants through one ancestor listener.
* **Form events** support validation and submission handling.
* **Keyboard and mouse events** respond to user interactions.
* **`removeEventListener()`** removes a registered listener.
* **Listener options** control capture, one-time execution, passive behavior, and cancellation through an abort signal.

## Recommended Learning Order

1. `addEventListener()`
2. The event object and its properties
3. Mouse and keyboard events
4. Form submission and `preventDefault()`
5. Event bubbling and capturing
6. `stopPropagation()`
7. Event delegation
8. Removing event listeners
9. Event listener options
10. Asynchronous event handlers

## Final Learning Goal

After practicing these topics, you should be able to build interactive web applications, validate forms, respond to keyboard and mouse actions, manage event propagation, and explain JavaScript event handling confidently in interviews.
