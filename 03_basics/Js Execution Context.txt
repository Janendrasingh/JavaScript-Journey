1. WHAT IS AN EXECUTION CONTEXT?
   ============================================================

## Definition:

An Execution Context is an environment in which JavaScript
code is evaluated and executed.

Whenever JavaScript executes code, it needs to keep track of:

1. Variables and their values.
2. Functions and how they are called.
3. The scope in which variables are accessible.
4. The current execution flow.

JavaScript uses an execution context to manage this information.

## REAL-LIFE EXAMPLE

Imagine you are taking an examination.

You have:

* An examination room.
* A question paper.
* A place to write your answers.
* Rules that determine what you can do.

Similarly, JavaScript creates an environment to manage and
execute your code.

## EXAMPLE

let name = "Janendra";

function greet() {
let message = "Hello";
console.log(message, name);
}

greet();

## EXPLANATION

JavaScript must keep track of:

1. The variable 'name' and its value.
2. The definition of the 'greet()' function.
3. The local variable 'message' when 'greet()' executes.
4. The values that need to be printed.

The execution context helps JavaScript manage these things.

## OUTPUT

Hello Janendra

2. TYPES OF EXECUTION CONTEXT IN JAVASCRIPT
===========================================

There are three commonly discussed categories:

1. Global Execution Context (GEC)
2. Function Execution Context (FEC)
3. Eval Execution Context

---

## A. GLOBAL EXECUTION CONTEXT (GEC)

## Definition:

The Global Execution Context is established when JavaScript
begins executing a script.

Example:

let a = 10;
const b = 20;

function add() {
console.log(a + b);
}

add();

## EXPLANATION

Before executing the statements normally, JavaScript
establishes the global execution environment.

The global environment keeps track of global declarations
and provides the environment for executing global code.

## IMPORTANT QUESTION: WHAT ABOUT 'this'?

In a browser's classic script, the global 'this' value is
generally the 'window' object.

Example:

console.log(this);

## Output:

Window

## IMPORTANT:

The value of 'this' depends on the execution environment
and script type.

For example:

* In a browser's classic script, top-level 'this' is
  generally 'window'.
* In a JavaScript ES module, top-level 'this' is 'undefined'.
* Node.js has its own environment-specific behavior.

## Remember:

The Global Execution Context is the starting execution
context for a JavaScript script.

---

## B. FUNCTION EXECUTION CONTEXT (FEC)

## Definition:

Whenever a function is called, JavaScript creates a new
Function Execution Context for that invocation.

Example:

function greet() {
let message = "Hello";
console.log(message);
}

greet();
greet();

## WHAT HAPPENS HERE?

1. JavaScript establishes the global execution context.
2. It processes the function declaration.
3. It encounters the first 'greet()' call.
4. A Function Execution Context is created for that call.
5. The function executes.
6. When the function returns, its execution context is
   removed from the active call stack.
7. The second 'greet()' call creates another Function
   Execution Context.

## IMPORTANT:

Calling a function multiple times creates separate
execution contexts for those invocations, even though
they execute the same function definition.

Each invocation has its own local execution environment.

---

## C. EVAL EXECUTION CONTEXT

JavaScript also has a special execution context associated
with the 'eval()' function.

Example:

eval("console.log('Hello from eval')");

## OUTPUT

Hello from eval

## EXPLANATION

Direct calls to 'eval()' can execute JavaScript code within
the surrounding execution environment and have special
scoping behavior.

However, 'eval()' is rarely needed in normal application
development.

It can create security and debugging problems, so avoid
using it unless you have a specific reason to do so.

3. THE TWO MAIN PHASES OF JAVASCRIPT EXECUTION
==============================================

Two important concepts help explain how JavaScript
initializes and executes code:

1. Creation Phase
2. Execution Phase

## EXAMPLE

var a = 10;

function greet() {
console.log("Hello");
}

var b = 20;

console.log(a);
console.log(b);

greet();

---

## A. CREATION PHASE

Before executing the statements normally, JavaScript
establishes the execution environment and processes
declarations according to their type.

For this example, we can simplify the initial environment
as follows:

## GLOBAL EXECUTION CONTEXT

a      -> undefined
greet  -> function definition
b      -> undefined

## WHY IS 'a' INITIALLY UNDEFINED?

Because 'var' declarations are initialized to 'undefined'
when their execution context is initialized.

Function declarations are also available before execution
reaches their textual position.

This behavior is commonly associated with HOISTING.

## IMPORTANT:

This is a simplified model for understanding 'var' and
function declarations. 'let' and 'const' have different
initialization behavior.

---

## B. EXECUTION PHASE

Now JavaScript executes the statements.

## STEP 1:

Code:

var a = 10;

Explanation:
The value of 'a' becomes 10.

## STEP 2:

Code:

function greet() {
console.log("Hello");
}

Explanation:
The function declaration was already processed during
initialization. JavaScript continues executing the program.

## STEP 3:

Code:

var b = 20;

Explanation:
The value of 'b' becomes 20.

## STEP 4:

Code:

console.log(a);
console.log(b);

## OUTPUT

10
20

## STEP 5:

Code:

greet();

Explanation:
The function is invoked, creating a Function Execution
Context for that invocation.

## OUTPUT

Hello

## COMPLETE OUTPUT

10
20
Hello

## IMPORTANT DISTINCTION

JavaScript does not simply execute every line twice.

The creation phase prepares the execution environment.
The execution phase evaluates statements and performs
their operations.

Also, 'let' and 'const' behave differently from 'var':
they cannot be accessed before initialization.

4. EXECUTION CONTEXT VS. CALL STACK
===================================

These concepts are related, but they are not the same.

## EXECUTION CONTEXT

1. Provides an environment for executing code.
2. Manages information such as variable bindings, scope,
   and execution state.
3. Is established for global code and function invocations.

## CALL STACK

1. Tracks active function calls and execution contexts.
2. Determines which function is currently executing.
3. Uses the Last In, First Out (LIFO) principle.
4. Pushes new execution contexts when functions are called
   and removes them when functions return.

## COMPARISON TABLE

Execution Context:
Provides the environment in which code executes.

Call Stack:
Tracks active execution contexts and function calls.

## EASY WAY TO REMEMBER

Execution Context = The environment.

Call Stack = The mechanism that tracks active execution.

============================================================
5. IMPORTANT POINTS TO REMEMBER
===============================

1. An Execution Context is an environment in which
   JavaScript code is evaluated and executed.

2. The three commonly discussed categories are:

   * Global Execution Context
   * Function Execution Context
   * Eval Execution Context

3. The creation phase establishes the execution environment
   and processes declarations according to JavaScript rules.

4. The execution phase evaluates statements and performs
   operations.

5. Function calls create new Function Execution Contexts.

6. The Call Stack tracks active function calls and
   execution contexts.

7. Hoisting describes observable behavior resulting from
   how declarations are processed and initialized.

8. 'var' is initialized to 'undefined' during initialization.

9. 'let' and 'const' cannot be accessed before initialization.

10. The scope chain allows JavaScript to find variables
    in the current and outer lexical environments.

14. INTERVIEW QUESTIONS ON EXECUTION CONTEXT
    ==================================================

Here are five important interview questions you should be able to answer.

## Q1. WHAT IS AN EXECUTION CONTEXT?

Answer:
An execution context is the environment in which JavaScript code is evaluated and executed. It keeps track of relevant information, such as variable and function bindings, scope, and the current execution state.

## Q2. WHAT ARE THE TWO MAIN PHASES OF AN EXECUTION CONTEXT?

Answer:
The two phases are:

1. Creation (Initialization) Phase:
   JavaScript establishes the execution environment and prepares variable and function bindings. The behavior depends on the type of declaration.

2. Execution Phase:
   JavaScript executes statements, evaluates expressions, assigns values, and performs operations.

## Q3. WHAT IS THE DIFFERENCE BETWEEN AN EXECUTION CONTEXT AND THE CALL STACK?

Answer:
An execution context provides the environment in which JavaScript code runs, while the call stack keeps track of active execution contexts and function calls.

In simple words:

* Execution Context = The environment where code executes.
* Call Stack = The structure that tracks which execution context is currently active.

## Q4. WHAT IS HOISTING?

Answer:
Hoisting describes how JavaScript processes declarations before their corresponding statements are reached during execution.

The behavior depends on the declaration type:

* var: The variable is initialized with undefined during the creation phase.
* let and const: The bindings are created but remain uninitialized until their declarations are evaluated. Accessing them earlier causes a ReferenceError because they are in the Temporal Dead Zone (TDZ).
* Function declarations: They can generally be called before their position in the code.

## Q5. WHAT HAPPENS WHEN A FUNCTION CALLS ANOTHER FUNCTION?

Answer:
When a function calls another function, JavaScript creates an execution context for the called function and places it on top of the call stack.

The called function executes first. When it finishes and returns, its execution context is removed from the call stack, and execution resumes in the calling function.

Example:

function first() {
console.log("First function started");
second();
console.log("First function ended");
}

function second() {
console.log("Second function executed");
}

first();

Output:
First function started
Second function executed
First function ended

# KEY POINTS TO REMEMBER

1. An execution context is the environment in which JavaScript code executes.
2. Execution contexts involve setting up bindings and executing code.
3. The call stack tracks active execution contexts.
4. Hoisting behavior differs between var, let, const, and function declarations.
5. A function call creates a new function execution context.
6. When a function returns, its execution context is removed from the call stack.
