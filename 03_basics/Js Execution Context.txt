1. What is an Execution Context?

An Execution Context is an environment in which JavaScript code is evaluated and executed.

Whenever JavaScript executes code, it needs to keep track of things such as:

Variables and their values.
Functions and how they are called.
The scope in which variables are accessible.
The current execution flow.

JavaScript uses an execution context to manage this information.

Real-life example

Imagine you are taking an exam.
You have:

An examination room.
A question paper.
A place to write your answers.
Rules that determine what you can do.

Similarly, JavaScript creates an environment to manage and execute your code.

Consider this example:
let name = "Janendra";

function greet() {
    let message = "Hello";
    console.log(message, name);
}

greet();
JavaScript must keep track of:

name and its value.
The definition of greet().
The local variable message when greet() executes.
The values that need to be printed.

The execution context helps JavaScript manage these things.

2. Types of Execution Context in JavaScript

There are three commonly discussed categories:

Global Execution Context (GEC)
Function Execution Context (FEC)
Eval Execution Context

Let's understand each one.

A. Global Execution Context (GEC)

The Global Execution Context is created when JavaScript begins executing a script.
let a = 10;
const b = 20;

function add() {
    console.log(a + b);
}

add();
Before executing the code line by line, JavaScript establishes the global execution environment.

Q. What about this?

In a classic browser script, the global this value is generally window.

console.log(this);

In a browser's classic script, this typically prints the Window object.

However, this behavior depends on the execution environment and script type. For example, top-level this behaves differently in JavaScript modules and in Node.js.

Remember: The Global Execution Context is the starting execution context for a JavaScript script.

B. Function Execution Context (FEC)

Whenever a function is called, JavaScript creates a new Function Execution Context for that invocation.

Consider:

function greet() {
    let message = "Hello";
    console.log(message);
}

greet();
greet();

What happens here?

JavaScript creates the global execution context.
It registers the function definition.
It encounters greet().
A Function Execution Context is created for that call.
The function executes.
Its execution context is removed from the active call stack when the function returns.
The second greet() creates another Function Execution Context.
Important: Calling a function multiple times creates separate execution contexts for those invocations, even though they execute the same function definition.

C. Eval Execution Context

JavaScript also has a special execution context associated with the eval() function.

For example:

eval("console.log('Hello from eval')");

Output:

Hello from eval

Direct calls to eval() can execute JavaScript code within the surrounding execution environment and have special scoping behavior.

However, eval() is rarely needed in normal application development. It can create security and debugging problems, so avoid it unless you have a specific reason to use it.


3. The Two Main Phases of JavaScript Execution

This is the most important part of the topic.

When JavaScript creates an execution context, two concepts are especially important:

Creation Phase
Execution Phase

Let's understand them using a simple example.
var a = 10;

function greet() {
    console.log("Hello");
}

var b = 20;

console.log(a);
console.log(b);

greet();

Phase 1: Creation Phase

Before executing the statements normally, JavaScript establishes the execution environment and processes declarations according to their type.
Why does a initially have the value undefined in this simplified model?

Because var declarations are initialized to undefined when their execution context is initialized.

The function declaration is also available before the program reaches its textual position.

This behavior is commonly associated with hoisting.

Phase 2: Execution Phase

Now JavaScript executes the statements.

First:

var a = 10;

The value of a becomes 10.

Next:

function greet() {
    console.log("Hello");
}

The function was already established during initialization, so JavaScript proceeds through its declaration.

Next:

var b = 20;

The value of b becomes 20.

Then:

console.log(a);
console.log(b);

Output:

10
20

Finally:

greet();

The function is invoked, creating a Function Execution Context.

Output:

Hello
Complete output
10
20
Hello

Important distinction: JavaScript does not simply execute every line twice. The creation phase prepares the environment; the execution phase evaluates statements and performs their operations.

Also, let and const behave differently from var: they are initialized differently and cannot be accessed before initialization. We will examine that next.
